# Changelog — v0.3.0

> Released: May 20, 2026

This release adds a per-object scripting system, a full screen-space text overlay with
editor integration, per-frame performance metrics, and play-mode snapshot management.
It also ships a corrective fix for geometry winding-order bugs that caused face-culling
artifacts on several primitives.

---

## New Features

### Per-Object Scripting System
*PR #7 & #8 — 2026-04-30 / 2026-05-01*

A lightweight, zero-overhead scripting layer lets you attach custom behaviour directly to
any scene object without touching the serialisable `World` state.

- New **`ObjectScript`** trait with three optional callbacks:
  - `on_start(id, world)` — called once on the first update after the script is attached.
    Use it to resolve string IDs into integer IDs and initialise per-object state.
  - `on_update(id, world, dt)` — called every frame (variable delta-time).
  - `on_fixed_update(id, world, dt)` — called at the fixed 60 Hz timestep.
- New **`ScriptRegistry`** (stored in `Scene`, not in `World`) with `attach` / `detach` /
  `has` methods. Internally uses a flat `Vec` + `HashMap` index for O(1) attach/detach and
  zero-allocation iteration on the hot path.
- **Deferred world mutations**: `spawn`, `delete`, and `reparent` calls made *inside* a
  script callback are safely queued and applied after the full iteration completes, preventing
  borrow conflicts and re-entrancy problems in both native and WASM environments.
- **Stale-script pruning**: when an object is deleted from the world its script entry is
  automatically removed on the next update pass (O(1) swap-remove).
- **Script borrow management**: JS-side callbacks cannot trigger re-entrant world mutations;
  the engine sets a guard flag and returns a clear error if violated.
- `ScriptRegistry::reset_started` re-triggers `on_start` for all scripts after a world
  snapshot restore (see below).

```rust,ignore
use vertra::script::ObjectScript;
use vertra::world::World;

struct Spinner { speed: f32 }

impl ObjectScript for Spinner {
    fn on_update(&mut self, id: usize, world: &mut World, dt: f32) {
        if let Some(obj) = world.get_mut(id) {
            obj.transform.rotation[1] += self.speed * dt;
        }
    }
}

// In on_startup:
scene.scripts.attach(planet_id, Box::new(Spinner { speed: 90.0 }));
```

### Screen-Space Text Overlay
*PR #12 — 2026-05-07*

A full GPU-accelerated 2-D text rendering layer for HUD labels, debug counters, and UI hints,
powered by `fontdue` for CPU rasterisation and uploaded as wgpu textures each frame.

- New **`TextOverlay`** stored on `Scene` — manages fonts and labels.
- **`TextOverlay::add_font(id, bytes)`** registers a TTF font under a string key.
- **`default-fonts`** feature flag bundles Google Sans, Roboto Serif, and Roboto Mono from
  `src/fonts/`; accessible as `DefaultFont::{Sans, Serif, Mono}`.
- **`TextOverlay::add_label(text)`** returns a **`TextLabelBuilder`** with a fluent API:

  | Builder method | Effect |
  |---|---|
  | `.at(x, y)` | Pixel position from top-left |
  | `.with_color([r, g, b, a])` | RGBA colour in `[0.0, 1.0]` |
  | `.with_font_size(px)` | Font size in pixels |
  | `.with_font(id)` | Select font by string ID |
  | `.with_zindex(z)` | Draw order (lower = further back) |
  | `.with_horizontal_alignment(…)` | `Left` / `Center` / `Right` / `Free` anchor |
  | `.with_vertical_alignment(…)` | `Top` / `Middle` / `Bottom` / `Free` anchor |
  | `.hidden()` | Start invisible |
  | `.build()` | Insert and return a `TextLabelHandle` |

- **`TextLabelHandle`** — a lightweight copyable token for mutation:
  `set_text`, `set_color`, `set_font_size`, `set_font`, `set_zindex`,
  `set_horizontal_alignment`, `set_vertical_alignment`, `move_to`, `show`, `hide`, `remove`.
- Labels stored in a `HashMap<usize, TextLabel>` for O(1) access by ID.
- Z-index controls draw order; labels added later default to a higher z-index so they
  appear on top.
- VTR serialisation extended to persist text labels including alignment settings.

```rust,ignore
let score = scene.text_overlay.add_label("Score: 0")
    .at(20.0, 20.0)
    .with_font_size(28.0)
    .with_color([1.0, 1.0, 1.0, 1.0])
    .with_horizontal_alignment(HorizontalAlignment::Left)
    .build();

// Later:
score.set_text(&mut scene.text_overlay, "Score: 42");
```

### Text Label Editor Integration
*PR #14 — 2026-05-09 to 2026-05-18*

Text labels are now full first-class citizens in the built-in scene editor.

- **Click** a label to select it; **Ctrl+click** to multi-select.
- **Drag** to reposition. On release the label's alignment is switched to `Free` so the
  new position survives re-bakes.
- **Edge-drag** (resize handles) to change font size interactively.
  A **draft mode** scales the existing GPU quad without re-rasterising during the drag;
  the full re-rasterisation only fires on drag-end, keeping the editor responsive.
- Rasterized pixel dimensions (`rasterized_w`, `rasterized_h`) stored per label to provide
  accurate hit-test and resize bounding boxes.
- **`VerticalAlignment`** added (`Top`, `Middle`, `Bottom`, `Free`) — mirrors the existing
  `HorizontalAlignment` enum and is fully integrated with the resize/move editor tools.
- New `on_editor_event` variants fired during label interactions:
  `LabelSelected`, `LabelDeselected`, `LabelDragStart`, `LabelDragEnd`,
  `LabelResizeStart`, `LabelResizeEnd`.

### Per-Frame Performance Metrics
*PR #10 — 2026-05-03*

Smoothed per-frame statistics are now available inside every callback through `FrameContext`.

| `FrameContext` field | Type | Description |
|---|---|---|
| `ctx.fps` | `f32` | Frames per second, averaged over the sample window |
| `ctx.frame_time_ms` | `f32` | Average frame time in milliseconds |
| `ctx.draw_calls` | `u32` | GPU draw calls issued last frame |
| `ctx.triangle_count` | `u32` | Triangles rendered last frame |

- Configurable **sample window** (default: `constants::frame_stats::DEFAULT_SAMPLE_WINDOW_SECS`).
- WASM binder exposes `stats_sample_window_secs` for JavaScript configuration.

### Play-Mode Snapshot Management
*PR #6 — 2026-04-28*

The engine now automatically snapshots the serialisable world state on every
`enable_editor_mode()` call and restores it when the user presses **Escape** to return to
play mode. This ensures each play session starts from a known, consistent scene.

- `World` is serialised to an in-memory snapshot on editor entry.
- On editor exit the snapshot is deserialised back, discarding any in-editor mutations.
- `ScriptRegistry::reset_started` is called after the restore so all `on_start` callbacks
  re-run against the fresh world, keeping per-script caches consistent.

## Bug Fixes

### Fixed Geometry Winding Order
*PR #16 — 2026-05-19*

All triangle and quad vertex orderings in the procedural geometry module were audited and
corrected. The wrong winding caused face-culling to discard front faces on several primitives,
producing invisible or partially-visible meshes under the default back-face cull mode.

Affected primitives: `Plane`, `Pyramid`, `Box`, `Cube` (and derived meshes).

## Breaking Changes

None. All new APIs are purely additive. Existing `Scene`, `World`, and `Window` builder
code compiles without modification.

## Upgrade Guide

Update your `Cargo.toml`:

```toml
[dependencies]
vertra = "0.3.0"
```

To opt into bundled fonts add the feature flag:

```toml
vertra = { version = "0.3.0", features = ["default-fonts"] }
```
